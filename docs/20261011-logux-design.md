# 「日志与配置中心体验优化」迭代设计 —— 日志可读性 / 命令展示 / 配置中心交互

> 状态:待评审(多轮确认无异议后开工)。
> 背景:用户反馈三处体验问题——①日志页原始 JSON 刷屏抓不住重点;②节点卸载命令弹窗阅读体验差;③配置中心交互混乱(失败版本刷屏/预览区残留 diff 着色/操作分散)。

## 1. 日志页重构(结构化日志视图)

**现状**:Caddy JSON 日志每行数百字符(含全部请求头)直接 `pre` 展示,信息密度极低。

**方案**:解析结构化展示 + 原始视图双模式。**组件选型:不引入第三方日志查看器**(react-lazylog 等面向原始文本流,做不了字段化筛选),用 **antd Table 虚拟滚动(v6 virtual)+ 自研 Caddy JSON 解析层**——日志格式是自家 Caddy 产出,解析最可控。

- 访问日志解析字段列:时间 / 方法(GET/POST 着色) / URI / 状态码(2xx 绿 3xx 蓝 4xx 橙 5xx 红) / 耗时 ms / 大小 / 来源 IP / 主机
- 错误日志解析字段列:时间 / 级别(info/warn/error 着色) / logger / 消息
- **行点击 → Drawer 展示完整 JSON**(格式化+复制),列表只留关键列
- **筛选工具栏**:关键字搜索(URI/IP/host)+ 状态码多选 + 方法多选;纯前端过滤
- 虚拟滚动支撑 1000 行上限;**非 JSON 行**(自定义日志格式)整行回退原始展示
- 保留**原始视图切换**(Segmented:结构化/原始),尊重高级用户习惯
- 自动刷新/暂停/行数选择等现有行为不变

## 2. 命令展示组件(节点安装/卸载共用)

**现状**:卸载命令 Modal 裸文本 + 一个复制图标,无步骤语义。

**方案**:自研 `CommandSteps` 组件,安装/卸载两处复用:

- **数据来源为后端结构化 API**(而非前端硬拆脚本字符串):`GET /nodes/uninstall-command` 与安装命令接口增加 `steps: [{desc, command}]` 字段(后端 InstallCommand/UninstallCommand 同步产出结构化步骤,`script` 字段保留供整体复制)
- 每步独立复制按钮 + **整体复制**按钮(复制完整 script)
- 前置条件/注意事项用 Alert 置顶(如"节点记录需先在面板删除")
- 卸载步骤化:①停止并禁用 agent 服务 ②移除 systemd 服务文件并重载 ③移除二进制 ④清理状态目录
- 安装命令(M3)同步迁移到该组件

## 3. 配置中心交互优化

**现状问题**(截图+运维视角):失败版本(测试残留 node offline)刷屏淹没有效版本;"对比当前"后预览区残留 diff 红绿着色未清除;回滚/对比操作按钮平铺拥挤;直编无未保存提示。

**方案**(用户+运维双视角):

- **版本历史**:
  - 状态过滤 Segmented(全部/已生效/失败)——默认"已生效",失败版本不再刷屏;失败原因收进折叠行
  - 操作收纳:每行保留状态+时间,对比/回滚收进行尾"···"下拉;回滚禁用态(失败版)显示原因
  - 列表分页(复用 tablePagination 模式,每页 10)
- **预览/编辑区**:
  - 修复:**切回预览或刷新后清除残留 diff 装饰**(对比会话结束后恢复纯高亮预览)
  - 直编模式:有未保存更改时标题显示标记 + 吸顶"保存/放弃"操作(复用 I6 SaveButton 模式);保存前 Caddyfile 校验失败错误定位到行
- **对比**:保留"对比当前";新增版本列表多选对比(勾选两版互 diff)
- **运维视角**:回滚确认 Dialog 保持带入口站点影响警告(D11);直编保存失败保持 422 原文透传

## 4. 验收标准

1. 日志页:结构化视图按列筛选/着色正确,行 Drawer 完整 JSON,1000 行滚动流畅,原始视图可切换,非 JSON 行不崩
2. 卸载/安装命令:步骤化展示+单步/整体复制可用,两处复用同一组件
3. 配置中心:失败版本过滤默认生效;对比后切回预览无残留着色;直编未保存标记与放弃可用;回滚确认含影响警告
4. 全部亮/暗主题目检;lint/build/既有测试绿

## 6. 日志后端检索 + 实时流式推送(用户确认纳入)

- **后端检索**:GET /api/v1/logs 增加可选参数 keyword(URI/IP/host/消息子串)与 status(逗号分隔状态码前缀,如 4,5);服务端在 tail 读取窗口(2MiB)内过滤后再取末尾最多 1000 条匹配行——更早的匹配行不在窗口内,不回溯(明确语义:检索范围=tail 窗口),前端筛选栏改为调服务端参数(输入防抖)
- **实时流式推送**:新增 SSE 端点 GET /api/v1/logs/stream?type=&keyword=&status= —— 服务端每 500ms 增量读取新行并推送;前端 EventSource 消费,自动重连,关闭连接即暂停;"自动刷新"开关切换轮询/流式两种模式,流式为默认
- 鉴权:SSE 用查询参数传 JWT(与终端 WS 同模式);权限点复用 logs:read
- 兼容:现有轮询接口保留(降级路径)

## 7. 配置中心多文件(片段管理,用户确认纳入)

- **模型**:v1 采用"附加片段"而非目录树——配置中心新增片段管理:多个具名片段(名称+Caddyfile 内容+启用开关),渲染时启用片段按创建顺序追加到主文件尾部(各片段须自包含合法块;**片段禁止包含全局块 {**(admin 指令等归主文件管辖,重复全局块非法,编辑器与校验双层拦截);片段仅作用于 local 主文件渲染,远程节点配置不受影响**;整体仍走校验管线,任一片段非法则整体下发失败)
- 落盘/备份/恢复/回滚:片段内容并入 ConfigVersion 快照与备份(备份格式 v2 增量字段 snippets,恢复纯增量 upsert 同 users 语义);回滚=恢复当时快照(含片段)
- **UI**:配置中心新增"片段"入口:列表(名称/启用开关/更新时间)+编辑器(同款 Monaco)+删除确认;片段变更走"预检→下发"同一管线并生成版本记录
- 非目标:子目录/import 通配符、片段间引用

# 设置页布局重构设计 — 迭代 I6

> 状态:待评审。与 notify-channels-design.md 同批实施。

## 1. 问题

当前设置页 4 个横排 Tabs 内堆了 11+ 个功能分组(常规 Tab 一页就有 5 组双列表单),视觉层级弱、扫读困难、新分组只能继续往里塞。

## 2. 新信息架构(左侧分类导航 + 右侧内容)

采用 antd 设置页标准模式:**`Tabs tabPosition="left"`**(左侧竖排分类,右侧内容区),每分类内容精简单列/规整双列:

| 分类(左) | 内容(右) |
| --- | --- |
| **Caddy 连接** | Admin API 地址、admin 监听地址 |
| **路径** | Caddyfile 落盘、访问/错误日志路径 |
| **安全** | 登录锁定阈值/时长 |
| **通知** | SMTP(服务器/端口/账号/密码/发件/收件+**发送测试邮件**)、Webhook(URL+**类型**+**发送测试消息**)、ACME 邮箱、到期 Webhook |
| **API Token** | 签发 + 列表(原样) |
| **备份与恢复** | 导出/导入(原样) |
| **头像** | Gravatar 镜像(预设+自定义) |
| **高级** | metrics 开关、global_extra |

- 通知合并为一个分类(SMTP+Webhook 同属"到期提醒渠道",原分散在证书与通知两处);
- 每分类独立保存按钮(现状即如此,保持);权限可见性沿用现有 RBAC(设置读全角色/写 admin);
- 头部大 Tabs 横排取消,统一左侧导航,分类名走 i18n。

## 3. 实施与验收

- 纯前端布局迁移,不改任何后端逻辑与字段;所有现有字段/按钮/权限不丢失(以现状字段清单逐一核对);
- 验收:浏览器亮/暗双主题逐分类目检布局对齐;功能回归(保存/测试邮件/测试消息/Token 签发/备份导出导入全链路)。

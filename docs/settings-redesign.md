# 设置页布局重构设计 — 迭代 I6

> 状态:待评审。与 notify-channels-design.md 同批实施。

## 1. 问题

当前设置页 4 个横排 Tabs 内堆了 11+ 个功能分组(常规 Tab 一页就有 5 组双列表单),视觉层级弱、扫读困难、新分组只能继续往里塞。

## 2. 新信息架构(左侧分类导航 + 右侧内容)

采用 antd 设置页标准模式:**`Tabs tabPosition="left"`**(左侧竖排分类,右侧内容区),每分类内容精简单列/规整双列:

| 分类(左) | 内容(右) |
| --- | --- |
| **常规** | Admin API 地址、admin 监听地址、**面板对外地址(panel_public_url,现无 UI 入口——本次补齐,agent 安装命令依赖;M4 验收时只能 API 补配)** |
| **安全** | 登录锁定阈值/时长 |
| **通知** | 事件源(ACME 邮箱 + 到期 Webhook URL 同行)→ Webhook 渠道区(类型 Select + 测试消息按钮同区)→ SMTP 渠道区(表单 + 测试邮件按钮尾部)→ 保存;测试按钮各归渠道不集中 |
| **API Token** | 签发 + 列表(原样) |
| **备份与恢复** | 导出/导入(原样) |
| **头像** | Gravatar 镜像(预设+自定义) |
| **高级** | metrics 开关、global_extra(证书存储路径 cert_storage_path **维持仅 env 管理,不设 UI**——误改会导致面板与 Caddy 失联,现有 settings 键仅作覆盖入口保留) |

- 通知合并为一个分类(SMTP+Webhook 同属"到期提醒渠道",原分散在证书与通知两处);
- 保存按钮统一为**吸顶保存栏**(右对齐,滚动常驻可见——长表单不再需要滚到底保存);权限可见性沿用现有 RBAC(设置读全角色/写 admin);
- 头部大 Tabs 横排取消,统一左侧导航,分类名走 i18n。

## 3. 实施与验收

- 后端唯一新增:`panel_public_url` 的 UI 表单项(键/白名单/读取链路均已存在,零后端改动);其余纯前端布局迁移,字段清单已逐一核对(设置键全集 18 项:16 项进 UI,smtp_password 脱敏交互与 cert_storage_path 仅 env 为有意排除);
- 验收:浏览器亮/暗双主题逐分类目检布局对齐;功能回归(保存/测试邮件/测试消息/Token 签发/备份导出导入全链路)。
